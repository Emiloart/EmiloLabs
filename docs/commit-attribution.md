# Commit Attribution and Metadata Policy

**Status:** Normative repository policy  
**Applies to:** Every commit and every contributor workflow in this repository

## 1. Purpose

GitHub derives contributor attribution from commit metadata, including author identity and recognized co-author trailers. A tool-generated `Co-authored-by` trailer can therefore cause an AI product or bot to appear as a repository contributor even when the commit was authored and submitted by the repository owner.

Emilo Labs distinguishes assistance from authorship. AI systems may assist with implementation, but they are not Git co-authors.

## 2. Normative rules

1. Git author and committer identities must identify the responsible human.
2. AI assistants, coding agents, bots, and automated tools must not be represented as authors or co-authors.
3. Do not include AI-related `Co-authored-by` trailers, bot co-author trailers, AI session URLs, session IDs, or private conversation references in commit messages.
4. Do not accept commit messages generated by an AI tool without reviewing the complete message and its trailers.
5. Human co-author trailers are allowed only for actual human contributors who made a substantive contribution and agreed to the attribution.
6. These rules apply to commits created locally, through IDE integrations, web interfaces, automation, GitHub Apps, and other agents.

This policy does not prohibit using AI tools. It prohibits assigning them Git authorship or co-authorship.

## 3. Enforcement layers

| Layer | Control | Purpose |
|---|---|---|
| Contributor instructions | `CONTRIBUTING.md` | Establishes the rule before work begins |
| Agent instructions | `AGENTS.md` | Makes the rule explicit to repository-aware coding agents |
| Local Git hook | `.githooks/commit-msg` | Rejects disallowed metadata before a local commit is created |
| Automated validation | `scripts/check-commit-message.mjs` | Implements the shared policy check |
| GitHub Actions | `.github/workflows/commit-metadata.yml` | Checks pushed commits and pull-request commit ranges |
| Branch protection | GitHub repository settings | Makes the pull-request check mandatory before merge |

The hook is not automatically activated by cloning a repository. Each local clone must run:

```bash
git config core.hooksPath .githooks
```

Repository administrators must also configure branch protection or a ruleset requiring the `Commit metadata policy` status check. A workflow that runs without being required is a detection mechanism, not a merge gate.

## 4. Disallowed metadata

The validator rejects:

- `Co-authored-by` trailers naming known AI assistants, coding agents, or bots.
- AI session metadata such as `Claude-Session`, `ChatGPT-Session`, or equivalent session references.
- Known AI coding-agent attribution labels in commit trailers.

The validator intentionally does not reject every human `Co-authored-by` trailer. Human co-authorship remains possible under the consent and substantive-contribution conditions above.

If a new AI tool is introduced, update the validator's identity patterns and add a test case before using that tool to create commits.

## 5. Commit creation workflow

Before committing:

1. Review `git status` and the complete staged diff.
2. Review the proposed commit subject, body, and trailers.
3. Ensure author and committer identities resolve to the responsible human.
4. Ensure no AI or bot co-author or session metadata is present.
5. Allow the local commit hook to run. Do not use `--no-verify`.
6. Confirm the GitHub Actions check passes on the resulting commit or pull request.

Example inspection commands:

```bash
git status --short
git diff --cached
git show -s --format=fuller HEAD
git show -s --format=%B HEAD
```

## 6. Correcting an attribution error

A published commit's metadata is immutable. Removing a co-author attribution from the branch's reachable history requires replacing the affected commit and updating descendant commits as necessary.

For a shared branch, this is a history rewrite. It must be authorized by the repository owner, performed with an expected-head/force-with-lease safeguard, and communicated to collaborators. Rewriting history can invalidate existing clones and open branches.

After correction, verify:

- The branch points to the replacement history.
- The affected commit message has no disallowed trailer or session metadata.
- The replacement commit preserves the intended source tree and human author identity.
- GitHub's contributor display is checked after its derived data has had time to refresh.

A commit that has merely become unreachable may remain accessible by its old SHA or in external clones and caches. Do not claim that every historical copy has been erased.

## 7. Exceptions

There are no exceptions for AI or bot Git co-authorship. A repository owner may revise this policy through an explicit documentation change, but an individual contributor or tool may not silently bypass it.
